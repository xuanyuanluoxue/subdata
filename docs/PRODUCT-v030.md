# SubData v0.3.0-beta 产品规划

> 产出方式：4 个独立子 Agent 并行头脑风暴（`pm-student` / `pm-power` / `pm-privacy` / `tech-lead`），
> 各自只读仓库、独立出提案，最后由主 Agent 汇总打分决策。
> 基线：`cae59b5`（B 线二期），最终合入 `feat/v0.3.0`，并在 v0.2.1（`1491fcb`）之上 rebase。

---

## 0. 一句话结论

v0.2.x 把「能跑」做完了（20 个 hook 生效、槽隔离成立、App 不崩）。
v0.3.0 的主题是 **「让用户看得见、切得动、救得回」**——
**不做任何新 hook、不改核心映射逻辑**，只在「可观测性 + 操作路径 + 自救」这三个面上补齐。

## 1. 三份 PM 的原始提案摘要

### 1.1 pm-student（普通学生用户视角）

> 用户画像：不懂 Xposed，装模块只为同一台手机登两个学习通账号（自己的 + 同学的），
> 怕把主账号数据搞坏、怕 App 更新后失效。
> 一句话判断：**当前这个模块是「给开发者用的工具」，不是「给学生用的产品」。**

| # | TOP5 想法 | 价值 | 核心依据 |
|---|---|---|---|
| S1 | 首次启用向导 + 状态自检清单（root / 已启用 / 已勾选 / 已注入 四步打勾） | 5 | `MainActivity.java:99-100` 直接进主界面，无任何引导；失效只显示死胡同文案「还没有运行记录」 |
| S2 | 把「slot」翻译成「账号 / 数据副本」+ 可起别名 + 显示内容标识 + **支持删除单个副本** | 5 | `strings.xml` 通篇「slot」；`item_slot.xml:38-44` 的 `tv_slot_meta` 被 `SlotActivity.java:282` 写死 `GONE`；`showActions` 没有删除项 |
| S3 | 切换合并为一步 + 用账号名确认 + 切到空副本时安抚文案 | 4 | `switchTo()` 只写 slot 文件，强停是另一个按钮，漏做等于没切 |
| S4 | 技术开关折叠进「高级模式」，小白只留「启用/停用」 | 4 | 首页把 5 个 hook 开关全铺给小白，文案是「hook getDataDir（高风险）」 |
| S5 | 一键备份/导出 + 「原始数据从未被改动」的可验证证明 | 4 | 唯一的写操作是**破坏性**的 `deleteControlDir`，没有任何备份能力 |

**它选的第一名**：S1 首次启用向导（「所有问题都始于不知道怎么开始用」）。

### 1.2 pm-power（效率工具玩家视角）

> 用户画像：装过几十个模块，在意粒度、可观测性、可自动化。

| # | TOP5 想法 | 价值 | 核心依据 |
|---|---|---|---|
| P1 | 一键切 slot（切换 + 自动 force-stop + 广播/快捷方式接入自动化） | 5 | 现在切号要 5~7 次点击且「切」和「停」分离（`SlotActivity.java:205-247`） |
| P2 | 修 `clone_on_first_run=false` 不建目录 + 补 DE 树 | 5 | `SubDataModule.java:119-125`、`DataCloner.java:57` |
| P3 | slot 删除 + 每槽体积 + last-used 元数据 | 4 | `tv_slot_meta` 占位已留，几乎白送 |
| P4 | 日志导出/分享 + 实时刷新 | 3 | `LogActivity` 只有复制/清空 |
| P5 | 多目标 App 的 UI 切换器（盘活 `setActiveTarget` 死代码） | 4 | `TargetStore.setActiveTarget()` 全仓库零调用 |

**它选的第一名**：P1 一键切 slot（「决定这模块是工具还是玩具」）。

### 1.3 pm-privacy（隐私与稳定视角）

> 先摆了两个**当前代码里已经存在**的隐患，再谈改进。

1. `DataCloner.ensureSlot`（`DataCloner.java:45-49`）发现槽目录存在但缺 `.cloned` 时，
   **只补标记、不重做克隆**，把半成品永久固化成成品；`copyTree`/`copyFile` 的 `IOException` 全被吞（`:89-91,:110-111`）。
2. README 说 `getCodeCacheDir` 不重定向（`README.md:129`），代码却 hook 了它（`SubDataModule.java:182`），
   而 `DataCloner.SKIP` 又跳过 `code_cache` —— **被重定向却从不创建**。

| # | TOP5 想法 | 风险 | 核心依据 |
|---|---|---|---|
| R1 | 槽目录完整性：无论 clone 开关，slot 根 + 标准子目录必须存在 | 高 | `cache`/`no_backup`/`code_cache` 被 SKIP 后没人建 |
| R2 | 半成品槽自愈（`.cloning` 进行中标记 + 完成才写 `.cloned`） | 高 | 最隐蔽的「数据会丢」场景，比崩溃更糟 |
| R3 | `slot` / `subdata.conf` 原子写 + 区分「不存在」与「损坏」 | 中高 | 切槽瞬间断电 → 静默回落 a，用户以为数据丢了 |
| R4 | 隐私收敛：日志最小化（去掉 `modulePath`）+ 控制目录暴露风险显式化 | 中 | `subdata/` 就在目标 App 自己的 dataDir 里，枚举即现形 |
| R5 | 崩溃逃生：**一键安全模式**（成本小）+ 务实版自动降级（成本中） | 中 | 用户只能去 LSPosed 取消勾选或手敲 su |

**它选的第一名**：R1+R2（「这两个不解决，稳定不丢数据就无从谈起」）。

**它额外点出的安全洞（本版必须处理）**：`TargetRepo` 的 `pkg` 参数没有校验，
`deleteControlDir` 的「双重校验」用的是同一个拼接公式，若 `pkg` 被篡改成 `..`，
`rm -rf /data/data/../subdata` 会删到 `/data/subdata`（`TargetRepo.java:19-21,146-154`）。

### 1.4 tech-lead（可行性定价，不是提需求）

对 18 个候选方向逐条给了「涉及文件 / 改动量 / 技术风险 / 能否单测」，并明确指出 3 个**已被误认为「没做」**的方向：

| 方向 | 实际状态 | 依据 |
|---|---|---|
| 主界面显示当前 slot | ✅ 已实现 | `MainActivity.java:218` |
| 一键新建槽 | ✅ 已实现 | `SlotActivity.createSlot` + `TargetRepo.createSlot` |
| 多 App 独立 slot | ✅ 底层天然成立，缺的只是界面切换器 | `SubDataModule.isTarget()` + 每个 App 独立 dataDir |

它给出的「1 小时能做完」清单是 6 项：自动建槽目录、建 DE 目录、每槽体积、一键切换（补 force-stop）、删除单槽、日志导出诊断包。
其中前两项与 v0.2.1 重叠，**本版不重复做**（见 §3）。

三个它判定为「技术上不成立」的方向值得单独记一笔：

- **通知小岛**：Android 没有公开的小岛 API，HyperOS 灵动岛是系统私有 UI，第三方只能发普通通知被系统折叠展示 → **不可行**。
- **加固壳自检**：模块自己（`com.xavier.subdata` 进程）读不到目标进程的 `/proc/self/maps` 和 classloader 痕迹，能做出来的只是「提示用户去开 Shamiko」，属于文档不是功能。
- **崩溃自动回退**：只能兜 Java 层未捕获异常；学习通是 `libDexHelper` 加固、大量 native，native 崩溃/OOM/被 kill 全拦不到，且**必须真机验证**（本线红线，碰不到真机），1 小时做不扎实。

## 3. 被否决的想法与理由（明确写清）

**架构类（永远不做，不是「这版不做」）**

| 否决项 | 理由 |
|---|---|
| 双实例同时在线（两个图标、两个进程并行） | 需要「工作资料 / 多用户」或虚拟化，超出「只改数据目录」的定位；对加固壳兼容极差。产品上必须对用户说清：**本模块只能切换，不能同时在线**。 |
| 设备指纹伪造 / 风控规避 | 越界且高风险，可能导致账号被风控甚至封号；模块定位是「只隔离数据」。 |
| hook native 层（PLT/inline hook `open`）拦 `.so` 写死路径 | 恰恰是加固壳/风控的重点检测对象，等于主动暴露 Xposed，直接击穿「未被 libDexHelper 检测」这个最大卖点。 |
| 在模块里做「反 Xposed 检测隐藏」 | 这是加载器侧（Vector/Zygisk denylist + Shamiko）的职责，模块内做反而增大被检测面。 |
| hook `File.listFiles()` 去隐藏 `subdata/` 目录 | 猫鼠游戏：native 层一读就现形，还给最热的 `File` 路径叠开销。 |
| 把控制目录挪出目标 App 私有目录 / 挪到系统分区 | 违反「不改系统分区、不 hook system_server」硬约束；且「App 自己 uid 一定读写得到」是当前设计的基石，改动是架构级决策，不该夹在一个小版本里。 |
| slot 数据加密 / 文件名混淆 | App 自己要按标准路径读写，加密后 Java/native 都不认，功能直接不可用。 |
| 云同步 slot 数据 | 同步的是登录态，隐私风险高、收益低。 |
| 用 Shizuku 替代 root | 目标用户是 KernelSU（已有 root），且模块本身依赖 LSPosed（也要 root），收益不匹配成本。 |
| Compose 重写 | 收益低、纯折腾，`docs/RESEARCH-UI.md` 已否决。 |
| 内置自动静默升级 | root 模块静默升级风险高，且当前无分发渠道。 |

**本版明确不做（有具体理由，不是「没时间」）**

| 否决项 | 本版理由 |
|---|---|
| 通知小岛 / 灵动岛 | 无公开 API，做不出「可点按切换的小岛」；只能退化成普通通知（而通知本身本线无法验证）。 |
| 通知栏常驻状态 | `POST_NOTIFICATIONS` 运行时权限 + Android 14 `foregroundServiceType` 强校验 + 后台周期性跑 `su`，坑多且**模拟器验不了**，留给人真机迭代。 |
| 崩溃自动回退 | 只能兜 Java 层异常（学习通 native 为主），且**必须真机验证**才能调阈值；本线红线不碰真机，做出来是「看起来有其实没有」的假安全。 |
| 首次启用向导 | 300~500 行纯 UI，且向导要讲的内容（体检、状态清单）必须先落地；顺序反了向导里全是空话。 |
| 槽快照导入导出 | zip-slip 校验 + SAF + `restorecon` 收尾三件套，安全面太大，1 小时做不扎实。 |
| 半成品槽自愈、slot/conf 原子写 | 两个都要动 `DataCloner` / `SlotConfig` / `RootShell`——正是并行开发的 v0.2.1 的改动区，冲突风险高。**列为 v0.3.1 首要项**（pm-privacy 认为这是最高危的数据丢失路径，理由成立，但需要一次不受干扰的迭代）。 |
| 删除 slot 前不加 pkg 校验就上线 | pm-privacy 明确反对「在补校验前扩展任何 `rm -rf`」。**采纳其前置条件**：本版先落 `TargetRepo.pkg` 校验，再上删除功能。 |

## 4. v0.3.0-beta 最终范围

一句话：**看得见（体积/体检）、切得动（一键）、救得回（诊断包/删槽）**。

| # | 功能 | 落点 | 为什么选它 |
|---|---|---|---|
| F1 | **每槽数据占用统计** | 新增 `SlotStats.java`（纯 Java）；`TargetRepo.slotSizes()` 一次 `du -sk` 统计全部槽；`SlotActivity` 列表显示体积；首页 chip 显示「a · 12.3 MB」 | 三位 PM 都提到「数据看不到」；`du` 一次调用即得，成本极低 |
| F2 | **首页一键切换 + 自动强停** | `TargetRepo.switchAndStop()`；`MainActivity` 新增槽 chip 行，点一下弹确认→切→停 | pm-power 的 TOP1、pm-student 的 TOP3、tech-lead 的 #4 三方共识 |
| F3 | **删除单个 slot** | `TargetRepo.deleteSlot()`（双路径校验）+ `SlotActivity` 动作菜单 + 双重确认 + 当前槽保护 | 唯一缺失的基础管理动作；补上 pkg 校验后风险可控 |
| F4 | **配置体检** | 新增 `HealthCheck.java`（纯 Java，返回带严重度的问题列表）；首页显示最严重一条 | 把 pm-privacy 的「会崩的组合」提前到用户点之前，且完全可单测 |
| F5 | **诊断包导出** | 新增 `Diagnostics.java`（纯拼装 + 单测）；`LogActivity` 按钮 → 写 App 外部私有目录 → FileProvider 分享 | 排障闭环；不碰 `/sdcard` 权限、不碰 root 打包 |
| F0 | **pkg 合法性校验**（前置） | `TargetRepo.validPkg()`，所有拼接路径的入口先校验 | pm-privacy 点名的 `..` 穿越洞，且是 F3 上线的前提 |

**刻意没做**：任何新 hook、任何 SystemUI/通知/前台服务、任何 zip 解包、任何 `DataCloner` 改动。
**新增纯 Java 类 3 个**（`SlotStats` / `HealthCheck` / `Diagnostics`），全部可 JVM 单测。
**新增单测 3 个文件 / 22 个用例**，与既有 22 个用例一起跑。

## 5. 三条 PM 视角的「没被采纳但有价值」的话（留档给 v0.4）

1. pm-student：「学生第一反应是『我主账号没了』」——切到空副本时必须给安抚文案。
   *本版已在新文案里写了这句（`slot_switch_confirm_stop`），但全界面文案重写留 v0.4。*
2. pm-privacy：`getCodeCacheDir` 被 hook 而 README 说不 hook，且 `DataCloner.SKIP` 跳过 `code_cache`。
   *这是真实缺陷，但改它要 reshape `DataCloner` 的 SKIP 表，归入 v0.3.1。*
3. tech-lead：「多 App 独立 slot 底层已天然成立，缺的只是界面」。
   *意味着这个功能几乎是白送的 UI 工作，v0.4 优先。*
